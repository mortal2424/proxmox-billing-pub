# Обновление безопасности HomeVlad

## Существующие установки

1. Переведите панель в режим обслуживания. Сохраните копию базы, конфигурацию, пользовательские загрузки и приватные тома. При необходимости ограничьте доступ к панели на прокси.
2. Вручную обновите исходники или пересоберите Docker-образ. Удалите оставшиеся от прежней установки `admin/test/`, `admin/backup_debug.php`, `admin/node_monitor.php`, `admin/metrics_debug.php`, `api/test_telegram.php`, `templates/vm_metrics.php` и корневые `test_*.php`. Удалите тестовые архивы и перенесите журналы из веб-корня либо закройте их на прокси. Для Apache сохраните поставляемый `.htaccess`. Для Nginx перенесите правила запрета из шаблона Docker и назначьте отдельный default vhost для неизвестных имён. Закройте прямой внешний доступ к Apache за прокси.
3. В обычной установке выполните из каталога сайта `php tools/migrate-account-security.php`. Нужны права `ALTER`, `CREATE` и `TRIGGER` на БД панели. Docker запускает миграцию при старте. Миграция добавляет ревизию пользователя, триггер отзыва прав, хеш для сброса, журнал одноразовых данных Telegram и индекс внутреннего ID гостя в таблицах метрик.
4. Очистите **только** сессии этого экземпляра в его файловом каталоге, Redis или другом настроенном хранилище. На общем хостинге уточните у провайдера каталог или префикс панели. Кеширующие прокси и долгоживущие процессы PHP перезапустите или очистите согласно своей конфигурации. Сессии прежнего формата и мобильные токены прежнего формата отклоняются. Клиентам нужно войти повторно, а для мобильной биометрии сначала войти с паролем и заново включить вход с устройства.
5. Настройте канонический HTTPS-адрес без пути в `HOMEVLAD_PUBLIC_URL` или добавьте в приватный `includes/config.php` значение `HOMEVLAD_CANONICAL_URL`. Docker берёт адрес из `DOMAIN`. Ссылки сброса, выданные до миграции, аннулированы. Пользователь может запросить новую ссылку.
6. Для удалённых бэкапов включите явный FTPS с TLS на сервере назначения. Сохраните адрес, каталог и имя пользователя. Используйте DNS-имя из сертификата сервера и доверенный CA. Кнопка проверки подключения использует тот же FTPS, что и загрузка. Старый FTP без TLS перестанет подключаться.
7. Проверьте повторный вход, сброс пароля, запуск сборщиков метрик и доступность резервных копий. Исторические точки без идентификатора экземпляра хранятся до штатной очистки. В пользовательские графики попадают точки, которые сборщик связал с конкретным внутренним ID. После миграции графики заполняются новыми измерениями.

В Docker PHP и задания cron работают без права записи в код. Обновления применяются заменой образа с сохранением томов БД, загрузок, архивов и приватных настроек. Веб-интерфейс может просматривать каталог, создавать копии и восстанавливать БД и загруженные файлы. После восстановления старой БД повторите миграцию до открытия панели и аннулируйте сессии. Код восстанавливается пересборкой из нужной версии. Для первичной настройки временно задайте `HOMEVLAD_ENABLE_INSTALL=1` и ограничьте доступ к установочным маршрутам на прокси своей сетью. Снимите флаг сразу после создания первого администратора.

При расследовании возможного использования прежнего отладчика сохраните защищённую копию журналов и проверьте административные операции, созданные учётные записи и настройки доступа. Удаление файлов из текущей поставки сохраняет историю Git.

## Подписи обновлений

Обновлятор умеет проверять отсоединённую подпись Ed25519 исходных байтов манифеста. Чтобы включить проверку:

1. Ответственный за выпуски генерирует ключ выпуска вне GitHub и защищает закрытую часть. Проверку и подписание можно выполнять с помощью PHP sodium.
2. Публикация подписывает содержимое `manifest.json` через `sodium_crypto_sign_detached`. Закодированная в Base64 подпись помещается рядом в `manifest.json.sig` в том же неизменяемом коммите. Каталог продолжает указывать хеш манифеста и идентификатор этого коммита.
3. Оператор получает Base64-представление 32-байтового публичного ключа по независимому доверенному каналу, сверяет его и указывает путь к файлу в `HOMEVLAD_UPDATE_PUBLIC_KEY`. В Docker файл можно разместить в подключаемом каталоге `/run/homevlad-license` только для чтения. После включения отсутствующая или неверная подпись блокирует установку.

Публичный ключ и подписи текущих пакетов ещё предстоит выпустить. Без настроенного доверенного ключа сохраняется прежний режим проверки SHA-256.

## Локальные регрессии

```sh
php tools/test-security-regressions.php
PHP_BIN=php bash tools/test-security-http.sh
```

Первая команда проверяет прикладную логику на SQLite. Вторая поднимает PHP только на loopback. Для проверки DDL и интеграции контейнеров используйте отдельный MariaDB и Docker-стек.
