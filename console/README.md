# Консоли Proxmox

PHP проверяет права пользователя и передаёт цель подключения через локальный
Unix-сокет. Браузер получает одноразовый код на 30 секунд. Прокси хранит
`PVEAuthCookie` и CSRF-токен в памяти и отправляет их только в Proxmox.
Для QEMU клиент получает билет конкретной VNC-сессии для RFB. Для LXC
прокси выполняет вход в termproxy самостоятельно.

На Debian нужен пакет `python3-aiohttp`. Установите `bridge.py` в
`/opt/homevlad-console` и используйте `homevlad-console.service` с пользователем
и группой, доступными PHP сайта. Путь к сокету в PHP и в сервисе должен
совпадать. На HomeVlad сервис слушает только `127.0.0.1:8765`.

Для Proxmox с частным CA задайте `PROXMOX_CA_FILE` в
`/etc/homevlad-console/environment`. Файл должен содержать проверенные
публичные CA кластера в PEM. Прокси проверяет цепочку и имя узла. Имя в
`proxmox_nodes.hostname` должно присутствовать в сертификате Proxmox.
Для отдельного узла можно задать `PROXMOX_CERT_PINS` как путь к JSON-словарю
`{"имя-узла:8006": "sha256-сертификата-в-hex"}`. Точный отпечаток заменяет
проверку CA только для указанной пары имени и порта. После смены сертификата
отпечаток требуется обновить. Проверьте доступность порта API с сервера биллинга и доступ учётной записи узла к консоли. Билет Proxmox запрашивается при подключении.

Установите статические клиенты из зафиксированных релизов под `console/assets`:

- noVNC v1.5.0, дерево релиза в `novnc/`, включая `core/` и `vendor/`.
- `@xterm/xterm@5.5.0` в `xterm/`, включая `lib/xterm.js` и `css/xterm.css`.
- `@xterm/addon-fit@0.10.0` в `fit/`, включая `lib/addon-fit.js`.

Подключите `nginx.conf` в HTTPS vhost, выполните `nginx -t` и перезагрузите
конфигурацию. Проверьте запуск из кабинета для своей ВМ и LXC, отказ для
чужой ВМ и запуск из двух списков админки. У браузера для проверки должна
быть только сессия биллинга.
