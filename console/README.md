# Консоли Proxmox

PHP проверяет права пользователя и передаёт цель подключения через локальный
Unix-сокет. Браузер получает одноразовый код на 30 секунд. Прокси хранит
`PVEAuthCookie` и CSRF-токен в памяти и отправляет их только в Proxmox.
Для QEMU клиент получает билет конкретной VNC-сессии для RFB. Для LXC
прокси выполняет вход в termproxy самостоятельно.

На Debian нужен пакет `python3-aiohttp`. Установите `bridge.py` в
`/opt/homevlad-console` и используйте `homevlad-console.service` с пользователем
и группой, доступными PHP сайта. Путь к сокету в PHP и в сервисе должен
совпадать. На HomeVlad сервис слушает только `127.0.0.1:8765`.

Для Proxmox с частным CA задайте `PROXMOX_CA_FILE` в
`/etc/homevlad-console/environment`. Файл должен содержать проверенные
публичные CA кластера в PEM. Прокси проверяет цепочку и имя узла. Имя в
`proxmox_nodes.hostname` должно присутствовать в сертификате Proxmox.
Для отдельного узла можно задать `PROXMOX_CERT_PINS` как путь к JSON-словарю
`{"имя-узла:8006": "sha256-сертификата-в-hex"}`. Точный отпечаток заменяет
проверку CA только для указанной пары имени и порта. После смены сертификата
отпечаток требуется обновить. Проверьте доступность порта API с сервера биллинга и доступ учётной записи узла к консоли. Билет Proxmox запрашивается при подключении.

Установите статические клиенты из зафиксированных релизов под `console/assets`:

- noVNC v1.5.0, дерево релиза в `novnc/`, включая `core/` и `vendor/`.
- `@xterm/xterm@5.5.0` в `xterm/`, включая `lib/xterm.js` и `css/xterm.css`.
- `@xterm/addon-fit@0.10.0` в `fit/`, включая `lib/addon-fit.js`.

Подключите `nginx.conf` в HTTPS vhost, выполните `nginx -t` и перезагрузите
конфигурацию. Проверьте запуск из кабинета для своей ВМ и LXC, отказ для
чужой ВМ и запуск из двух списков админки. У браузера для проверки должна
быть только сессия биллинга.

В разделе **Настройки → Настройки VNC** панель показывает состояние сокета,
доступные HTTPS-адреса и срок действия билета. Для сохранения настроек задайте
`HOMEVLAD_CONSOLE_SETTINGS` как путь к JSON вне веб-корня, доступный для записи
пользователю PHP. Срок действия можно задать от 15 до 90 секунд.
Прокси сообщает допустимые адреса через локальный сокет. Основной адрес задаёт
`CONSOLE_ORIGIN`, дополнительные адреса перечисляются через запятую в
`CONSOLE_ADDITIONAL_ORIGINS`. Билет использует один конкретный адрес.

Для отдельного окружения задайте `CONSOLE_SOCKET`, `CONSOLE_PORT` и
соответствующие настройки PHP и Nginx. PHP принимает настройку
`HOMEVLAD_CONSOLE_SOCKET` в каталоге `/run/homevlad-console` или
`/run/homevlad-console-<имя>`. Доступ к Unix-сокету, CA, отпечатки
сертификатов узлов и сетевой маршрут прокси настраивает оператор сервера.

## Хостинг без root

Веб-панель может работать на обычном PHP-хостинге с расширением cURL и
исходящим HTTPS. Прокси запустите в своём окружении, где есть Python с aiohttp,
публичный HTTPS с поддержкой WebSocket и сетевой доступ к API Proxmox. Прокси
получает учётные данные узлов по HTTPS для открытия сеанса, поэтому размещайте
его в доверенном окружении.

1. Сгенерируйте общий секрет командой `openssl rand -hex 32`. Передайте его
   прокси через `CONSOLE_ISSUER_SECRET`. В этом режиме Unix-сокет не требуется.
2. Задайте `CONSOLE_ORIGIN` адресом панели, например `https://panel.example.org`.
   Опубликуйте у прокси `POST /console/issuer` и WebSocket `/console/socket`
   с действительным публичным TLS-сертификатом. При TLS-терминации запускайте
   прокси в приватной сети или на loopback и проксируйте заголовок Authorization.
3. На PHP-хостинге задайте параметры ниже через окружение PHP либо через
   `homevlad-console.php` на один уровень выше веб-корня панели. Ограничьте
   доступ к файлу учётной записью сайта. Путь к JSON также должен быть вне
   веб-корня, а его каталог должен быть доступен PHP на запись.

```php
<?php
return [
    'HOMEVLAD_CONSOLE_BROKER' => 'https://console.example.org',
    'HOMEVLAD_CONSOLE_BROKER_SECRET' => 'секрет из первого шага',
    'HOMEVLAD_CONSOLE_SETTINGS' => '/home/account/private/console-settings.json',
];
```

В разделе **Настройки → Настройки VNC** проверьте состояние внешнего прокси.
Веб-консоль подключается к нему напрямую по WSS. Внешний режим поддерживает
веб-консоль. Нативные приложения используют локальный режим панели.
