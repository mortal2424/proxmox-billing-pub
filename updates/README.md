# Пакеты обновления HomeVlad

Панель читает каталог `updates/index.json` в ветке `main` официального репозитория. Каждый выпуск ссылается на неизменяемый Git-коммит манифеста и его SHA-256. Манифест содержит исходную и новую версии, changelog, Git-коммит файлов и контрольные суммы исходного и нового содержимого каждого файла.

Для одного из уже установленных обновляторов допустимое имя пакета состоит из номера и суффикса без второго дефиса. Для перехода с `2.5.1-Pre-release1` запись каталога использует совместимое имя `2.5.1-rc1.1` в полях `version` каталога и манифеста. В `display_version` указывается имя выпуска `2.5.1-Pre-release1.1`. Оба имени должны иметь одинаковый порядок сравнения. Каталог и манифест проверяются по прежним SHA-256. Новый обновлятор принимает оба имени и показывает `display_version`.

## Подготовка выпуска

1. Проверьте изменения на отдельной установке. Включите новый номер в `includes/version.php`.
2. Зафиксируйте исходники, которые должны войти в выпуск.
3. Подготовьте текст changelog и выполните генератор из корня репозитория.

   ```sh
   python3 tools/build-update.py --base <исходный-коммит> --target <новый-коммит> --from-version 2.5.1-beta7 --version 2.5.1-beta8 --changelog /путь/к/changelog.txt
   ```

4. Проверьте и зафиксируйте созданный `updates/<версия>/manifest.json`.
5. Добавьте запись в `releases` каталога с полями `version`, `commit` (полный SHA коммита манифеста), `sha256` (хеш файла манифеста) и `summary`.
6. Опубликуйте каталог в `main`. Пользователь сначала проверяет пакет в меню обновлений, читает changelog и список конфликтов, затем запускает установку.

Текущий формат поддерживает добавление и замену файлов. Удаление файлов и миграции схемы базы требуют отдельной реализации и проверки до включения в формат пакета. Генератор останавливается при удалениях. Конфигурация подключения, пользовательские загрузки, журналы, резервные копии и зависимости Composer исключены из пакета. Dockerfile, файлы Compose и каталог `docker/` также исключены. Изменения этих файлов применяются при пересборке контейнеров из исходников выпуска.

## Проверки и восстановление

Оригинальное содержимое определяется по SHA-256. Если локальный файл отличается и от исходного, и от целевого содержимого, панель показывает конфликт и блокирует весь пакет. Администратор сохраняет свои изменения и вручную переносит изменения выпуска. Затем запускает проверку повторно.

Перед заменой сохраняются оригиналы. Запуски сериализованы файловой блокировкой. Версия и история записываются в БД транзакционно после установки файлов. При обрабатываемой ошибке установщик восстанавливает исходные файлы и возвращает панель в рабочий режим после успешного отката файлов и БД. Если откат не подтверждён, журнал сохраняется.

Если PHP-процесс аварийно завершился, остаётся `backups/updates/recovery.json`. Следующий запуск блокируется до ручной проверки. Журнал содержит рабочий каталог и список файлов. Оригинал каждого существовавшего файла находится в рабочем каталоге под именем SHA-256 относительного пути с суффиксом `.before`. Сохраните журнал до восстановления. После восстановления файлов или завершения проверенного пакета администратор сверяет версию в БД и удаляет журнал.

Первичная установка нового обновлятора на старую панель требует отдельного обновления его входных файлов. После этого пакеты устанавливаются через меню обновлений. В Docker штатный обновлятор показывает каталог и предпросмотр. Для установки пересоберите образ из нужной версии, сохраните тома и пересоздайте контейнеры. Образ содержит зависимости, расписание cron, Nginx и сервис консоли.

### Подпись выпуска

Для пакетов HomeVlad используйте отдельный ключ Ed25519. На машине публикации
создайте закрытый seed вне рабочей копии. Команда выведет открытый ключ.

```bash
php tools/sign-update.php keygen /secure/homevlad-update.seed > /secure/homevlad-update.pub
```

После генерации окончательного манифеста подпишите его точные байты. Сохраните
`manifest.json` и `manifest.json.sig` в одном коммите до добавления ссылки на
коммит и SHA-256 манифеста в каталог.

```bash
php tools/sign-update.php sign /secure/homevlad-update.seed updates/ВЕРСИЯ/manifest.json \
  > updates/ВЕРСИЯ/manifest.json.sig
```

Перед включением проверки убедитесь, что подписан пакет, который предстоит
установить. Передайте открытый ключ операторам отдельно от пакета по доверенному
каналу. Разместите открытый ключ вне веб-корня и укажите его путь в
`HOMEVLAD_UPDATE_PUBLIC_KEY` для веб-процесса и фонового обновлятора. Обоим
нужен доступ на чтение файла. Для проверки требуется расширение PHP Sodium.
Закрытый seed хранится только у издателя.

В обязательном режиме задайте `HOMEVLAD_UPDATE_SIGNATURE_REQUIRED=1` и
`HOMEVLAD_UPDATE_PUBLIC_KEY` одновременно для веб-процесса и фонового
обновлятора. Без ключа или подписи установка прервётся до изменения файлов и БД.
Значение `0` сохраняет прежнюю совместимость: если ключ задан, подпись
проверяется, а если ключ отсутствует, используется прежняя проверка SHA-256.

До включения завершите согласованный переход со старых неподписанных выпусков.
Если промежуточный пакет требуется после включения режима, издатель должен
опубликовать подписанный манифест именно этого пакета. Обновление каталога
само по себе не добавляет подписи к историческим пакетам.

В Docker поместите только открытый ключ в каталог `HOMEVLAD_UPDATE_TRUST_DIR`
(по умолчанию `.docker-private/update-trust`), задайте
`HOMEVLAD_UPDATE_PUBLIC_KEY=/run/homevlad-update-trust/homevlad-update.pub`
и пересоздайте контейнер Apache. Каталог подключается только для чтения.
При отказе проверьте наличие файла и права чтения от имени PHP, наличие
`manifest.json.sig` в коммите каталога и соответствие ключа издателю.
`HOMEVLAD_LICENSE_REQUIRED` управляет лицензией панели независимо.
